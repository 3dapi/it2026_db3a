# 데이터베이스

배틀그라운드와 로스트아크

선정 이유: 배틀그라운드는 한 판이 끝나면 결과만 남는 세션형 게임이고 과금이 외형에 한정된다. 로스트아크는 캐릭터와 장비가 계속 누적되는 영속형 게임이고, 과금 재화가 거래소를 거쳐 장비 성장으로 이어진다. 데이터 생성 방식과 과금 구조가 대조적이어서 비교하기 적합하다. 

## 배틀그라운드

### 데이터베이스 분석

| 시스템 | 설명 | 저장 데이터 |
| --- | --- | --- |
| 계정 | 플레이어 식별, 레벨, 유료 재화 | 닉네임, 레벨, G-COIN |
| 매치 | 맵과 모드를 골라 한 판 진행 | 맵, 모드, 시작 시각 |
| 전적 | 매치가 끝난 뒤의 개인 결과 | 순위, 킬 수, 피해량 |
| 치장 | 캐릭터·무기 외형 | 아이템 종류, 보유 목록 |
| 상점 | G-COIN으로 치장 아이템 판매 | 상품, 가격, 판매 기간, 구매 내역 |

### 관계와 카디널리티

| 관계 | 카디널리티 | 설명 |
| --- | --- | --- |
| match - match_participant | 1 : 1..N | 매치에는 최소 1명 이상 참가한다. |
| account - match_participant | 1 : 0..N | 매치를 한 번도 하지 않는 계정도 있다 |
| account - inventory | 1 : 0..N | 치장 아이템이 없는 계정도 있다 |

| cosmetic - product | 1 : 0..N | 같은 아이템이 시즌·할인별로 여러 상품으로 판매된다 |
| account - purchase | 1 : 0..N | 무과금 계정은 구매 기록이 없다 |
| product - purchase | 1 : 0..N | 한 상품은 여러 계정이 구매한다. |

### 과금 데이터 구조

배틀그라운드는 유료 재화 G-COIN으로 게임 내 아이템을 구매하는 구조다. 판매되는 아이템은 능력치에 영향이 없는 치장 아이템이다.

- 현금 충전 → account.g_coin 증가
- 상품 구매 → purchase 행 추가, account.g_coin 차감
- 아이템 지급 → product.cosmetic_ID 로 inventory 행 추가

| 시스템 | 설명 | 저장 데이터 |
| --- | --- | --- |
| 원정대 | 계정 하나에 캐릭터 여러 개, 재화 공유 | 원정대 레벨, 골드, 로열 크리스탈 |

| 레이드 | 아이템 레벨 제한이 있는 주간 콘텐츠, 골드 보상 | 레이드 정보, 클리어 기록 |

| 관계 | 카디널리티 | 설명 |
| --- | --- | --- |
| account - game_character | 1 : 1..N | 원정대에는 캐릭터가 최소 1개 있다 |
| game_character - character_equipment | 1 : 0..N | 캐릭터가 장비를 여러 개 착용한다. |
| item - character_equipment | 1 : 0..N | 같은 장비를 여러 캐릭터가 착용한다 |
| game_character - raid_clear | 1 : 0..N | 캐릭터는 여러 레이드를 클리어한다 |

| account - market_listing(판매자) | 1 : 0..N | 계정은 여러 아이템을 등록한다 |
| account - market_listing(구매자) | 0..1 : 0..N | 팔리기 전에는 구매자가 없다 |
| item - market_listing | 1 : 0..N | 한 아이템이 여러 번 거래된다. |
| account - purchase | 1 : 0..N | 무과금 계정은 결제 기록이 없다. |

### 과금 데이터 구조

로스트아크는 현금으로 산 유료 재화가 게임 내 경제를 거쳐 캐릭터 성장으로 이어지는 구조이다.

- 현금결제 → purchase 행 추가, account.royal_crystal 증가
- 재화 환전 →크리스탈을 골드로 교환해  account.gold 증가
- 재료 구매 → market_listing에 buyer_account_ID·sold_AT 기록
- 장비 재련 → character_equipment.refine_level 증가
- 재련 실패 → character_equipment.artisan_energy 누적

## 두 게임의 데이터베이스 구조 비교

| 비교 항목 | 배틀그라운드 | 로스트아크 |
| --- | --- | --- |
| 데이터 생성 방식 | 매치마다 결과 로그 추가 | 성장 상태 갱신 + 기록 누적 |
| 계정 구조 | 계정 = 플레이어 (1단계) | 원정대 → 캐릭터 (2단계) |
| M:N 해소 테이블 | match_participant, inventory | character_equipment, raid_clear |
| 연결 테이블의 키 | 복합키 2개 | 복합키 1개 + 대리키 1개 |
| 동일 테이블 이중 참조 | 없음 | market_listing → account (판매자/구매자) |
| 누적 상태 데이터 | 없음 | refine_level, artisan_energy |
| 과금 모델 | 치장형 | 성장 연계형 |
| 과금 → 게임 플레이 연결 | 없음 | 있음 (거래소 → 장비) |
| 테이블 / FK 수 | 7 / 7 | 8 / 9 |

### 공통점

두 게임 모두 account를 중심으로 데이터가 1:N 관계로 뻗어 나간다. 유료 재화 잔액은 account에 두고,
실제 결제 내역은 purchase에 따로 기록한다. 또 M:N 관계를 연결 테이블로 해소하고, 그 테이블에 관계 고유의 속성을 저장한다는 점이 같다. 

### 차이점

1. 데이터 생성 방식: 배틀그라운드는 매치가 끝날 때마다 match_participant에 행이 계속 추가되는 로그 중심 구조다. 로스트아크는character_equipment 처럼 기존 행의 값이 갱신되는 상태 중심 구조다
2. 계층 구조: 로스트아크는 원정대와 캐릭터를 나눠야 해서 계층이 하나 더 있다. 그래서 공유 재화는 account에, 개별 성장은 game_character에 둔다 
3. 과금 구조: 배틀그라운드는 product→inventory 로 끝나는 짧은 경로이고 플레이데이터와 분리돼 있다. 로스트아크는 크리스탈 → 골드→ 거래소→ 재련으로 이어지는 긴 경로이고, 장비 성장과 직접 연결된다.
